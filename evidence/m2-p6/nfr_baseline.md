## 7. 运行方式

```bash
# 一键运行（自动启动/停止服务）
bash scripts/run_nfr_baseline.sh

# 自定义端口
bash scripts/run_nfr_baseline.sh --port 8106

# 快速模式（减少采样和持续时间）
bash scripts/run_nfr_baseline.sh --quick

# 服务已运行时
bash scripts/run_nfr_baseline.sh --skip-start --skip-stop
```

## 8. 关键发现

1. **健康检查极快**：/v1/health P99 仅 3.1ms，10 并发下 RPS 达 548
2. **Skill 同步延迟高**：outreach/meeting P50 约 5s（确定性模式），生产环境将更高
3. **previsit Skill 异常快**：P50 仅 0.62ms，可能未执行完整逻辑（确定性模式直接返回）
4. **异步提交延迟适中**：P50 约 858ms，但并发下延迟急剧上升（10并发 P50 达 10s）
5. **健康检查并发线性好**：50 并发 RPS 546，100 并发 RPS 506（轻微下降）
6. **所有场景零错误率**：确定性模式下无请求失败

## 9. 备注

- 所有测试在确定性模式下运行（无 LLM API 调用），延迟不含外部网络开销
- 生产环境下延迟将显著高于基线值（取决于 LLM API 响应时间）
- SQLite 文件大小增长取决于请求类型和负载模式
- 并发测试中如出现错误率 >5%，需分析服务端日志定位瓶颈

- 原始数据见 `evidence/m2-p6/nfr_benchmark_results.json`
