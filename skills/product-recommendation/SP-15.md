# SP-15 产品适配与综合方案（三段式产品推荐）

面向对公客户经理的"一户一策候选决策支持"。输出为**产品适配/组合子方案**，不是完整客户服务建议书，也不代表授信/定价/产品/合规审批。SP-15 保持为 GITS 看到的**稳定业务门面**；KERT 内部拆成可观测步骤，不向 GITS 暴露多个不稳定 Skill。

## 1. 与 SP-20（客户服务建议书）的关系（唯一口径）

- **SP-15** = 一次受控决策运行：`硬过滤 → 需求能力匹配 → 客户经理确认`，产出 `ProductRecommendationProposalVersion`。
- **SP-20** = 顶层建议书生成，在 CH07 产品推荐章节**消费** GITS 传入的已决定推荐子方案 + 产品解读快照，**不再自行跑产品推荐**。
- 推荐决定（HG-D01 的 `APPROVE`）≠ 建议书 G3 正式审批。

## 2. 三段式（同一 ProductRecommendationRun 内的三个受控阶段）

### 第一段：硬约束过滤（Eligibility）
对每个产品版本依次检查：权限/数据用途 → 产品有效性 → 监管禁止 → 客户与机构准入 → 产品前置 → 互斥与存量冲突 → 销售边界。
结果闭集：`ELIGIBLE / INELIGIBLE / UNKNOWN / REVIEW_REQUIRED`。
`INELIGIBLE` 不得被软评分覆盖；`UNKNOWN` 不得按满足处理；每条结论必须 `ruleId+ruleVersion+inputFactRefs+result+reasonCode`。

### 第二段：需求—能力匹配与排序（Fit）
仅对 `ELIGIBLE` 计算。输入含客户事实快照、已确认需求、互动记录、交易/授信事实、外部事件、产品能力、组合规则、知识版本。
需求状态闭集：`VERIFIED_FACT / HUMAN_CONFIRMED / INFERRED_NEED / UNKNOWN / CONFLICT`。`INFERRED_NEED` 只作核实建议，不作强推介理由。
`FitScore = Σ(wi × mi)` 权重由产品域 Owner 按版本配置；只用于已合格候选内部排序。

### 第三段：客户经理人工确认（HumanGate）
由 GITS 通过 `HG-D01 / D01_PRODUCT_RECOMMEND` 执行 `APPROVE / MODIFY / REJECT / HOLD`。批准后仅形成内部服务方案草案。

## 3. KERT 内部可观测步骤（不对外暴露）

| 步骤 | 组件 | 性质 | 输出 |
|---|---|---|---|
| 0 | RecommendationInputValidator | 确定性 | 输入/权限校验 |
| 1 | ProductUniverseResolver | 确定性 | 有效产品全集 |
| 2 | HardEligibilityRuleExecutor | 规则 | EligibilityResult + RuleExecutionTrace |
| 3 | NeedProfileResolver | 规则+模型辅助 | 带状态/证据的 NeedProfile |
| 4 | NeedCapabilityMatcher | 规则/小模型 | 分维度匹配 |
| 5 | CandidateRanker | 可配置排序 | Eligible 候选排序 |
| 6 | PortfolioConstraintChecker | 规则 | 组合互斥/依赖/顺序 |
| 7 | RecommendationExplanationAssembler | 模板+LLM辅助 | 可读解释/条件/缺口 |
| 8 | EvidenceBundleAssembler | 确定性 | EvidenceBundle + 内容哈希 |

LLM 只参与需求归纳、解释与文字组织，不决定硬规则结果，不补造缺失事实。

## 7. 不变量（fail-closed，机器可测）

```text
INV-01 Active(ProductVersion)=false → 不得进入正式候选
INV-02 Eligibility=INELIGIBLE → rankScore/fitScore = null
INV-03 Eligibility=UNKNOWN → 不得按 ELIGIBLE 处理
INV-04 CandidateReason → 至少一条 EvidenceRef
INV-05 HardRule → 一个已批准 Owner + 一个权威来源
INV-07 KERT 不可达 → 禁止 GITS 本地生产推荐回退
INV-08 ProductVersion/RuleVersion 变化 → 下游 STALE
INV-09 AI 输出 → 不得直接创建授信/定价/审批/写回动作
INV-10 权威证据冲突 → 禁止确定性解读
```
