# SK-FRONT-005 承诺话术生成

## 概述

| 项目 | 内容 |
| --- | --- |
| 技能ID | SK-FRONT-005 |
| 技能名称 | 承诺话术生成 |
| 技能类型 | 生成 |
| 风险等级 | 高 |
| 关联知识域 | KD-01（客户知识域）、KD-04（流程知识域） |
| 关联知识条目 | KI-FRONT-004（事实承诺事项：历史沟通中形成的承诺事项，附沟通记录、话术和行动计划） |
| 关联规则 | RUL-FRONT-004（话术事实引用规则：只引用已核验事实） |
| 关联工具 | T-LLM-001（LLM 服务：生成话术、问题、解释） |
| 对应任务 | TASK-FRONT-005（事实承诺事项提取与话术生成） |

**服务对象**：对公客户经理（访前话术准备）、客户经理助理（跟进事项整理）。

**核心价值**：从客户历史沟通记录中提取事实承诺事项（如"客户承诺月底前提供报表""银行承诺下周出具授信方案"），按时间线展示，并针对每项承诺生成基于事实的沟通话术和行动计划，让客户经理拜访时"有据可依、有的放矢"，避免遗忘或凭空追问。

## 适用范围

1. 客户经理拜访前，需要整理客户此前承诺/待办事项并准备跟进话术时。
2. 多轮沟通后需要按时间线梳理承诺兑现情况时。
3. 需要把历史承诺转化为本次拜访的提问要点时。
4. 交接客户时，需要快速了解历史承诺与待办时。
5. 客户承诺未兑现、需要提醒或追问时。
6. 作为访前作战单"承诺话术"模块的输入素材时。

## 何时使用

- 访前作战单编制流程中，TASK-FRONT-005（事实承诺事项提取与话术生成）被触发时。
- 用户说"客户之前答应过的事帮我整理成话术""基于历史承诺生成提问话术""把客户承诺做成跟进卡片"时。
- 输入包含 ```customerId```，需要基于历史沟通记录生成承诺卡片时。

## 何时不要使用

- 无历史沟通记录可提取（首次拜访无承诺史）时：应输出"无历史承诺"占位，不虚构承诺。
- 仅需一般性拜访寒暄话术、不涉及承诺跟进时。
- 承诺事项涉及未核验事实时：不得生成无依据话术，引用缺失处必须标注"待核实"。

## 默认工作流

1. **确认输入**：校验 ```customerId```（必填），读取可选增强字段（customerName / goal / 沟通记录片段）。
2. **拉取历史沟通记录（T-CRM-001 / 录音转写）**：获取 CRM 历史拜访记录和访后录音转写文本。
3. **提取承诺事项（T-LLM-001）**：由语义 LLM 基于沟通记录提取承诺/待办事项，每条包含：
   - 承诺描述、承诺方（客户/银行）、状态标签（已完成/待反馈/逾期未完成）；
   - **事实引用**：引用原始沟通记录（沟通时间、渠道、参与人员、对话摘要、客户原话），引用缺失处标注"待核实"。
4. **时间线组织**：按承诺时间顺序组织，形成承诺时间线。
5. **生成沟通话术（T-LLM-001）**：针对每条承诺生成话术，包含四要素（RUL-FRONT-004）：
   - ①引用的事实出处（📌标注）；
   - ②面向的角色；
   - ③核心话术文本；
   - ④预期目标。
6. **生成行动计划**：针对每条承诺生成标准化行动建议（责任人、截止时间、具体行动路径）。
7. **生成输出**：按 references/output-schema.md 组装承诺卡片列表。
8. **自检与交付**：对照"交付标准"checklist 自检，通过后交付访前报告组装（SK-FRONT-001）或直接交付客户经理。

## 核心分析框架

### 5.1 承诺提取要素（KI-FRONT-004，KE-FRONT-004-01~04）

| 要素 | 内容 | 类型 |
| --- | --- | --- |
| KE-FRONT-004-01 | 沟通记录摘要：沟通时间、渠道、参与人员、对话摘要（200 字内）、客户原话（1-2 句代表性引语） | 事实（K-Type-F） |
| KE-FRONT-004-02 | 承诺内容及状态：承诺描述、承诺方（客户/银行）、状态标签（已完成/待反馈/逾期未完成） | 事实/规则（K-Type-F/R） |
| KE-FRONT-004-03 | 沟通话术：引用的事实出处（📌）、面向角色、核心话术文本、预期目标 | 流程（K-Type-P） |
| KE-FRONT-004-04 | 行动计划：责任人、截止时间、具体行动路径 | 流程（K-Type-P） |

### 5.2 话术生成原则（RUL-FRONT-004）

- **只引用已核验事实**：话术中的事实引用必须带来源标签（沟通时间/渠道/原话）；
- **引用缺失处标注"待核实"**：无法溯源的事实不得写入话术正文；
- **面向角色明确**：话术须指明面向客户哪个角色（财务总监/总经理/采购等）；
- **冲突项不得回避**：若与事实对账冲突清单（SK-FRONT-004 输出）相关，话术必须给出处理口径。

## 风险与边界

- **免责声明**：本技能输出为访前话术准备参考，不构成法律承诺或合同条款；承诺跟进须以双方确认记录为准。
- **禁止行为**：禁止虚构承诺事项或客户原话；禁止引用未核验事实生成话术；禁止删除"待核实"标注。
- **待核验标注**：引用缺失处（无法溯源的事实）必须标注"待核实"，话术不得包含无依据表述。
- **合规边界**：处理客户沟通记录须遵守行内客户信息保护规定，最小化采集、按需使用。

## 信息不足时的处理

- 无 ```customerId```：请求补充客户编号或客户名称；无法提供则终止。
- 无历史沟通记录：输出"无历史承诺"占位，说明原因，不虚构承诺。
- 承诺事实引用缺失：标注"待核实"，话术按降级（仅提示性提问）生成。
- 沟通记录不全：仅提取可得记录中的承诺，缺失部分标注缺口。

## 交付标准

- [ ] 每条承诺含承诺描述、承诺方、状态标签、承诺/截止时间。
- [ ] 每条承诺含事实引用（来源标签），引用缺失处标注"待核实"。
- [ ] 话术含四要素（事实出处/面向角色/核心话术/预期目标），只引用已核验事实。
- [ ] 每条承诺含行动计划（责任人/截止时间/行动路径）。
- [ ] 承诺按时间线组织，无虚构承诺。
- [ ] 输出符合 references/output-schema.md 结构。
