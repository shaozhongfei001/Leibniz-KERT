# SK-FRONT-003 八维研判

## 概述

| 项目 | 内容 |
| --- | --- |
| 技能ID | SK-FRONT-003 |
| 技能名称 | 八维研判 |
| 技能类型 | 判断 |
| 风险等级 | 中 |
| 关联知识域 | KD-08（数据与智能知识域） |
| 关联知识条目 | KI-FRONT-002（产业链八维研判） |
| 关联工具 | T-MARKET-001（市场慧眼智能体） |
| 对应任务 | TASK-FRONT-003（产业链八维研判） |

**服务对象**：银行对公客户经理（访前准备阶段）。

**核心价值**：通过获取企业相关行业/产业的各维度分析结果，与客户实际情况进行分析（对应知识条目 KI-FRONT-002），在客户拜访前快速形成对客户所在产业链的系统性判断，输出"八维卡片 + 综合结论"，帮助客户经理带着清晰的产业视角与谈资上门，提升访前作战单的产业洞察深度。

## 适用范围

1. 客户经理在访前准备阶段，需要了解客户所在产业链的整体态势。
2. 新客户首访前，需要对陌生行业快速建立认知框架。
3. 存量客户经营出现波动时，需要研判其所在产业环境是否发生系统性变化。
4. 行业政策、市场行情发生重大变化（如新产业政策出台、原材料价格剧烈波动）后的应对性研判。
5. 对公授信尽调前，需要形成产业层面的初步判断作为辅助参考。
6. 客户分层分类经营中，需要按产业链景气度对客户进行排序与画像。
7. 撰写访前作战单"产业研判"板块时，需要标准化的八维素材输入。
8. 与客户沟通产业链金融方案（如供应链金融、设备更新贷）时，需要产业依据支撑。

## 何时使用

- 访前作战单编制流程中，TASK-FRONT-003（产业链八维研判）被触发时。
- 客户经理输入客户行业代码（industryCode），需要八个维度的评分与综合经营结论时。
- 需要引用最新产业政策原文、行业指数走势等时效性信息时。

## 何时不要使用

1. 客户行业归属未确定（industryCode 缺失或无法识别）时，不要直接执行评分——先核实行业分类。
2. 不需要产业层面判断、仅需单户财务分析时，不要使用本技能。
3. 对客户进行授信审批决策时，不要以本技能输出作为唯一依据——本技能仅为访前研判参考。
4. 行业数据源不可用、市场慧眼智能体无法返回结果时，不要虚构维度数据。
5. 客户行业极其小众、公开数据基本为空时，不要强行打分——按"信息不足时的处理"降级。

## 默认工作流

1. **读取输入**：解析输入参数，取得必填字段 ```industryCode```，读取可选的客户补充信息（客户名称、区域、主营产品等）。
2. **界定产业范围**：根据 ```industryCode``` 确定客户所属行业/产业链，与 KI-FRONT-002 产业链知识条目交叉核对产业边界与上下游链条。
3. **调用八维分析**：将 ```industryCode``` 传入市场慧眼智能体 T-MARKET-001，获取政策、市场、技术、供应链、区域、风险、指数、竞争力八个维度的分析结果。
4. **逐维核验证据**：对返回的每个维度核验证据来源、发布时间与时效性；政策维度优先核对最新产业政策原文（含发文机关与文号）。
5. **逐维评分**：按照"核心分析框架"中的评分规则，为每个维度给出 1-5 分评分，并注明评分依据。
6. **标注证据等级**：为每个维度标注证据充分度：明确依据 / 部分依据 / 证据不足-待核实。
7. **综合研判**：平衡各维度（尤其是相互矛盾的信号），形成综合经营结论，列出不确定性说明与待核实事项清单。
8. **输出八维卡片**：按 ```references/output-schema.md``` 的结构输出 JSON 结果，并按"输出要求"中的模板渲染八维卡片。
9. **交付自检**：对照"交付标准"checklist 逐项复核，通过后交付访前报告组装（SK-FRONT-001 bank-front-report-assembler）。

## 核心分析框架

八维研判对客户所在产业链从以下八个维度进行分析，每个维度按 1-5 分评分（5 分为最有利/最健康，1 分为最不利/风险最高）。评分必须基于证据，不得凭印象打分；证据不足时按"信息不足时的处理"降级标注。

### 1. 政策维度——产业政策支持/限制

**判断口径**：国家及地方产业政策的支持或限制方向（鼓励类/允许类/限制类/淘汰类），是否列入负面清单，有无专项资金、税收优惠、准入限制。

| 分数 | 判断标准 |
| --- | --- |
| 5 | 列入鼓励类/国家战略支持方向，且有专项资金或税收优惠落地 |
| 4 | 明确支持（鼓励类或区域重点扶持），政策细则基本到位 |
| 3 | 中性——无明确支持亦无明确限制 |
| 2 | 限制类或产能过剩预警，政策边际收紧 |
| 1 | 淘汰类/负面清单/环保红线，面临强制退出压力 |

**输出要求**：引用政策原文时应注明发文机关、文号与年份。

### 2. 市场维度——供需景气度

**判断口径**：行业供需格局（供不应求/供需平衡/供过于求）、产能利用率、开工率、产品价格走势、订单景气度。

| 分数 | 判断标准 |
| --- | --- |
| 5 | 高景气：供不应求、价格上行、订单饱满 |
| 4 | 景气向好：供需偏紧、价格稳中有升 |
| 3 | 平稳：供需基本平衡、价格窄幅波动 |
| 2 | 走弱：供过于求、价格下行、订单减少 |
| 1 | 深度低迷：严重过剩、价格跌破成本线 |

### 3. 技术维度——技术迭代风险

**判断口径**：技术路线成熟度、技术迭代速度、被替代风险、行业研发投入水平、客户技术卡位。

| 分数 | 判断标准 |
| --- | --- |
| 5 | 技术路线成熟稳定，迭代风险低 |
| 4 | 技术较稳定，存在渐进式升级但不构成威胁 |
| 3 | 存在一定迭代压力，技术路线尚未完全收敛 |
| 2 | 技术迭代风险较高，新路线对现有产品形成冲击 |
| 1 | 面临颠覆性替代风险，现有技术路线濒临淘汰 |

### 4. 供应链维度——上下游稳定性

**判断口径**：上游原材料供给的稳定性与集中度、下游需求稳定性、断链风险、库存与账期情况。

| 分数 | 判断标准 |
| --- | --- |
| 5 | 上下游高度稳定，供给与需求均可预期 |
| 4 | 较稳定，偶有波动但不影响经营 |
| 3 | 一般，存在季节性波动或单一供应商依赖 |
| 2 | 明显波动，原材料涨价或下游压价压力大 |
| 1 | 断链风险高，关键环节受制于人 |

### 5. 区域维度——区域产业集聚与政策

**判断口径**：客户所在区域的产业集聚度、园区配套完善度、区域产业政策支持力度、交通与区位优势。

| 分数 | 判断标准 |
| --- | --- |
| 5 | 区域产业生态完善、集聚度高、政策优惠突出 |
| 4 | 区域产业基础较好，配套与政策较完善 |
| 3 | 一般，有一定产业基础但集聚效应不强 |
| 2 | 较弱，配套不完善或政策支持不足 |
| 1 | 区域产业配套薄弱，孤岛式经营 |

### 6. 风险维度——信用/合规风险信号

**判断口径**：行业信用事件与违约率、合规处罚记录、环保安全事件、经营异常名录、舆情负面信号。

| 分数 | 判断标准 |
| --- | --- |
| 5 | 无负面信号，行业信用环境良好 |
| 4 | 基本无异常，个别边缘性提示 |
| 3 | 存在个别风险提示（如行业个别主体违约） |
| 2 | 出现明显风险信号（多起信用事件/处罚/经营异常） |
| 1 | 重大风险事件频发，行业性风险暴露 |

### 7. 指数维度——行业指数走势

**判断口径**：行业指数近期走势（月度/季度）、相对大盘表现、行业景气指数、估值水平。

| 分数 | 判断标准 |
| --- | --- |
| 5 | 强势上行，显著跑赢大盘 |
| 4 | 温和上行，略强于大盘 |
| 3 | 震荡整理，与大盘基本同步 |
| 2 | 下行，弱于大盘 |
| 1 | 持续大跌，景气指标恶化 |

### 8. 竞争力维度——客户在产业链中的竞争地位

**判断口径**：客户市场份额与规模排名、议价能力、技术壁垒、客户与供应商集中度、与行业平均水平的对比。

| 分数 | 判断标准 |
| --- | --- |
| 5 | 行业龙头或细分领域龙头，议价能力强 |
| 4 | 第一梯队，具备一定技术与规模壁垒 |
| 3 | 中游水平，跟随行业平均 |
| 2 | 较弱，同质化竞争激烈 |
| 1 | 边缘化，市场份额持续萎缩 |

## 输入要求

输入遵循 ```references/input-schema.md``` 定义的 JSON 结构，必填字段为 ```industryCode```（客户行业代码）；其余为客户补充信息（可选），用于将行业八维分析结果与客户实际情况相结合（对应 KI-FRONT-002 的知识要点）。最低可用输入示例见 ```assets/example-input.json```。模拟输入数据位于 ```references/mock-input-data.json```，供开发调试、离线调用与评测注入。

## 输出要求

输出遵循 ```references/output-schema.md``` 定义的 JSON 结构：八个维度的评分 + 综合结论。同时按下述模板输出"八维卡片"（对应任务 TASK-FRONT-003 的输出 = 八维卡片 + 综合结论）。

## 风险与边界

1. **免责声明**：本技能输出为访前研判参考，不构成授信审批、投资或任何交易决策的依据；最终决策须结合客户尽调与行内风控制度。
2. **禁止凭单一维度下结论**：禁止仅依据某一维度（如仅凭政策利好或仅凭指数下跌）给出综合结论；综合结论必须基于多维证据交叉印证。
3. **禁止行为**：禁止虚构、编造证据与数据；禁止将模型推测当作事实陈述；禁止未经核验引用过期政策；禁止泄露客户敏感信息。
4. **待核验标注**：所有无法溯源、或发布时间过久、或来源为二手转述的信息，必须在对应维度标注"待核验"。
5. **风险等级**：本技能风险等级为"中"，输出涉及产业判断，需对证据链的完整性与时效性负责。

## 信息不足时的处理

1. 任一维度证据不足时，该维度标注 **"证据不足-待核实"**，评分按中性档（3 分）处理，并在依据中注明"证据不足，按中性处理"。
2. 若明确依据的维度少于 6 个，不得输出正式综合结论，应返回 ```status: insufficient``` 并列出缺失维度，建议补充数据源后再研判。
3. 政策维度优先引用最新产业政策原文；若无法获取原文，标注"政策原文待核实"，并说明所引用二手信息的来源。
4. 综合结论必须平衡多维矛盾信号，明确标注不确定性及其对结论的影响方向，并列出待核实事项清单。

## 交付标准

交付前逐项自检，全部通过方可交付：

- [ ] 输入包含合法 ```industryCode```，且已界定客户所属产业链范围
- [ ] 八个维度均有评分，证据不足维度已标注"证据不足-待核实"
- [ ] **评分必填且不得在组装中丢失**：输出 JSON 的 ```dimensions[].score```（1-5 整数）为必填字段；供 SK-FRONT-001 组装作战单时，```battleOrder.sections.eightDimension``` 必须携带逐维评分与依据，**禁止仅输出定性描述而无评分**
- [ ] 至少 6 个维度有明确依据（不足时已按降级流程处理）
- [ ] 政策维度已尽力引用最新产业政策原文（引用时含发文机关与文号；无法获取时已标注待核实）
- [ ] 每个维度评分均有判断要点与依据说明，无凭空评分
- [ ] 综合结论平衡了多维矛盾信号，未凭单一维度下结论
- [ ] 不确定性已标注，待核实事项已列出清单
- [ ] 输出符合 ```references/output-schema.md``` 结构，八维卡片模板完整
- [ ] 待核验信息均已标注，无虚构数据
