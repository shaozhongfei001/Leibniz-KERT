# SK-FRONT-004 事实对账与冲突检测

## 概述

| 项目 | 内容 |
| --- | --- |
| 技能ID | SK-FRONT-004 |
| 技能名称 | 事实对账与冲突检测 |
| 技能类型 | 判断 |
| 风险等级 | 中 |
| 关联知识域 | KD-01（客户知识域）、KD-05（风险管理知识域） |
| 关联知识条目 | KI-FRONT-003（行内变动行为：客户在行内近期关键变动指标及冲突检测结果） |
| 关联规则 | RUL-FRONT-001（冲突检测规则集） |
| 关联工具 | T-CORE-001（行内交易及财务指标）、T-EXT-001（外部工商/产业数据） |
| 对应任务 | TASK-FRONT-004（行内变动行为事实对账） |

**服务对象**：对公客户经理（访前准备阶段）、对公授信审查岗（指标核验）。

**核心价值**：把客户在行内的近期关键变动指标（营收、授信使用率、用电量、代发薪、结算量等）与外部工商/产业数据交叉校验，自动检测数据冲突、异常和逻辑不一致，生成冲突清单，让客户经理在拜访前就知道"哪些数字对不上、需要向客户核实什么"，避免带着错误事实上门。

## 适用范围

1. 客户经理拜访前，需要核对客户在行内的关键变动指标是否与外部数据一致。
2. 授信尽调前，需要对营收、用电量等指标的合理性做交叉验证。
3. 贷后回访时，需要发现客户经营指标异常波动或矛盾信号。
4. 发现用电量、代发薪、结算量等信号与营收趋势背离时。
5. 需要生成"待核实"清单供现场拜访提问时。
6. 作为访前作战单"事实对账"模块的输入素材时。

## 何时使用

- 访前作战单编制流程中，TASK-FRONT-004（行内变动行为事实对账）被触发时。
- 输入包含 ```customerId```，需要核对行内关键变动指标与外部数据一致性时。
- 需要自动检测数据冲突与逻辑异常（如"用电量上升 30% 但营收下降 20%"）时。

## 何时不要使用

- 仅需查询单个指标数值、不需要交叉校验时。
- 无行内指标数据或外部数据可核对时（应转入"信息不足时的处理"）。
- 需要出具审计级别的事实核验结论时（本技能输出为访前参考，冲突项以"待核实"标注）。

## 默认工作流

1. **确认输入**：校验 ```customerId```（必填），读取可选增强字段（customerName / industryCode / creditCode）。
2. **拉取行内关键变动指标（T-CORE-001）**：以 ```customerId``` 为入参，获取近半年营收（含同比）、现有授信使用率、近 3 个月用电量/进出口额、近 6 个月代发薪、近 3 个月结算量五类指标（对应 KI-FRONT-003 的 KE-FRONT-003-01~05）。
3. **拉取外部对照数据（T-EXT-001）**：获取外部工商/产业数据（行业景气、同行业平均营收增速等），作为交叉校验参照。
4. **交叉校验与冲突检测（RUL-FRONT-001）**：按预设的事实对账规则集对上述多维指标进行交叉校验，检测三类异常：
   - **逻辑矛盾**：如"用电量上升 30% 但营收下降 20%"；
   - **信号背离**：如代发薪持续下滑但结算量大幅上升；
   - **数据异常**：如授信使用率超过合理区间、结算量环比剧烈波动。
5. **生成冲突清单**：逐项列出冲突项、涉及数据源、触发规则编号（RUL-FRONT-001-xxx），并给出建议的核实问题。
6. **标注数据缺口**：显式列出缺失指标（如授信使用率/代发薪/结算量/用电量等）的数据缺口清单，不得仅列可得指标。
7. **生成输出**：按 references/output-schema.md 组装指标列表 + 冲突清单 + 数据缺口清单。
8. **自检与交付**：对照"交付标准"checklist 自检，通过后交付访前报告组装（SK-FRONT-001）或直接交付客户经理。

## 核心分析框架

### 5.1 行内关键变动指标（KI-FRONT-003，KE-FRONT-003-01~05）

| 要素 | 指标 | 口径说明 | 数据源 |
| --- | --- | --- | --- |
| KE-FRONT-003-01 | 近半年营收 | 近 6 个月结算账户累计经营性收入，附同比变化率 | T-CORE-001 |
| KE-FRONT-003-02 | 现有授信使用率 | 已用授信额度占总授信额度比例 + 剩余可用额度 | T-CORE-001（信贷系统） |
| KE-FRONT-003-03 | 近 3 个月用电量/进出口额 | 月度用电量（千瓦时）及环比/同比，经营活跃度客观替代指标，需客户授权 | T-EXT-001（授权数据） |
| KE-FRONT-003-04 | 近 6 个月代发薪 | 代发工资专户发放薪酬总额及月度趋势，交叉验证用工规模 | T-CORE-001 |
| KE-FRONT-003-05 | 近 3 个月结算量 | 全渠道资金交易笔数及总金额，附同比/环比 | T-CORE-001 |

### 5.2 冲突检测规则（RUL-FRONT-001）

| 规则类型 | 典型场景 | 处理 |
| --- | --- | --- |
| 逻辑矛盾 | 用电量 +30% 但营收 -20% | 列为冲突，标注"待核实"，给出核实问题 |
| 信号背离 | 代发薪持续下滑但结算量大幅上升 | 列为冲突，提示用工与资金活跃度背离 |
| 数据异常 | 授信使用率 > 100% 或结算量环比剧烈波动 | 列为异常，建议核实数据口径 |

每条冲突标注规则编号（RUL-FRONT-001-xxx），便于追溯。

### 5.3 显性呈现原则

- 冲突、异常、数据缺口不得静默吞掉，必须写入输出清单；
- 每条冲突附建议的核实问题（可直接转化为访前提问话术）；
- 未经权威源确认的数据一律标注"待核实"。

## 风险与边界

- **免责声明**：本技能输出为访前对账参考，不构成审计结论或授信决策依据；冲突项须经现场核实后确认。
- **禁止行为**：禁止将"待核实"冲突当作已核实事实陈述；禁止删除、弱化冲突或数据缺口；禁止虚构指标数值。
- **待核验标注**：未经行内权威源确认或跨源不一致的数据必须标注"待核实"；用电量等外部授权数据标注"需客户授权"。
- **合规边界**：处理客户交易与用电数据须遵守行内数据安全与客户信息保护规定。

## 信息不足时的处理

- 无 ```customerId```：请求补充客户编号或客户名称 + 统一社会信用代码；无法提供则终止。
- 某项指标缺失：列入 ```dataGaps``` 显式标注缺失 + 原因 + 补数动作，不得静默忽略。
- 外部对照数据不可用：以行内数据为准，交叉校验项标注"外部数据不可得"，冲突检测仅覆盖可得数据。
- 无法达到最低输出要求（无任何可得指标）：输出缺口清单 + 说明，不虚构指标。

## 交付标准

- [ ] 五类指标（营收/授信使用率/用电量/代发薪/结算量）均有条目，缺失指标在 ```dataGaps``` 显式列出。
- [ ] 每条指标标注数值、口径、数据时点、来源与状态（verified/pending/missing）。
- [ ] 冲突清单逐项含冲突描述、规则编号（RUL-FRONT-001-xxx）、涉及数据源、核实问题。
- [ ] 冲突、异常、数据缺口未被删除或弱化。
- [ ] 未经确认数据全部标注"待核实"，用电量标注"需客户授权"。
- [ ] 输出符合 references/output-schema.md 结构。
