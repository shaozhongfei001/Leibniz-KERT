# SK-FRONT-007 产品组合推荐

## 概述

| 项目 | 内容 |
| --- | --- |
| 技能ID | SK-FRONT-007 |
| 技能名称 | 产品组合推荐 |
| 技能类型 | 判断 + 生成 |
| 风险等级 | 高 |
| 关联知识域 | KD-02（产品知识域）、KD-01（客户知识域） |
| 关联知识条目 | KI-FRONT-006（产品候选组合）、KI-RULE-002（产品准入与互斥制度，源自 SRC-PRODUCT-001 产品知识卡 2026Q2） |
| 关联规则 | RUL-FRONT-003（产品硬约束规则） |
| 关联工具 | T-PRODUCT-001（产品组合引擎）、T-LLM-001（LLM 服务） |
| 对应任务 | TASK-FRONT-007（产品候选组合推荐） |
| 服务对象 | 对公客户经理 + 产品经理 |

**核心价值**：综合客户 KYC 痛点、实时沟通记录中的需求表达和市场慧眼信号三源输入（对应 KI-FRONT-006），匹配候选产品并标注三档匹配度标签（高匹配/组合备选/待核实），应用产品准入与互斥硬约束过滤（KI-RULE-002 / RUL-FRONT-003），输出候选产品列表与主推/交叉组合建议，让客户经理带着"推荐什么、为什么推荐、还需核实什么"上门。

## 适用范围

1. 客户经理访前准备阶段，需要明确客户可营销产品清单时。
2. 客户 KYC 痛点清晰（如现金流紧张、应收账款高企）需要匹配产品方案时。
3. 客户沟通记录中出现明确需求表达（如扩产、供应链融资）需要产品响应时。
4. 市场信号（如行业景气上行）提示客户存在融资/结算需求时。
5. 需要评估产品准入条件与互斥规则时。
6. 需要形成主推产品与交叉销售组合建议时。
7. 作为访前作战单"产品组合"模块的输入素材时。

## 何时使用

- 访前作战单编制流程中，TASK-FRONT-007（产品候选组合推荐）被触发时。
- 输入包含 ```customerId```（+ ```needs``` 需求摘要），需要匹配候选产品与组合建议时。
- 需要标注匹配度（高匹配/组合备选/待核实）与待核实条件时。

## 何时不要使用

- 无客户 KYC 痛点、沟通需求或市场信号任一输入时：输出"输入不足"说明，不凭空推荐。
- 仅需查询产品目录（不涉及客户匹配）时。
- 需要出具正式授信方案或产品承诺时（本技能输出为候选建议，最终以准入审批为准）。

## 默认工作流

1. **确认输入**：校验 ```customerId```（必填）与可选 ```needs```（需求摘要）。
2. **归集三源输入（T-LLM-001）**：汇总 ①KYC 痛点（来自 KYC 画像）、②沟通记录需求表达（来自沟通摘要）、③市场信号（来自市场慧眼）。
3. **候选产品匹配（T-PRODUCT-001）**：基于三源输入检索匹配候选产品，输出产品名称（KE-FRONT-006-01）与产品描述（KE-FRONT-006-03，标准文本）。
4. **匹配度标注（RUL-FRONT-003）**：基于硬约束校验结果和需求映射评估，为每个候选产品标注三档匹配度标签（KE-FRONT-006-02）：①高匹配；②组合备选；③待核实。标签由产品组合规则引擎根据三源融合计算生成，附规则说明链接。
5. **硬约束校验（KI-RULE-002 / RUL-FRONT-003）**：应用产品准入与互斥制度（产品准入条件、客户类型限制、监管禁止项、组合互斥规则）过滤候选产品；不满足硬约束的产品进入"硬约束未通过"清单并说明原因。
6. **生成匹配依据（KE-FRONT-006-04）**：为每个候选产品提供可追溯的匹配依据，引用具体输入来源（KYC 痛点/沟通记录/市场信号），标注来源类型与原始出处。
7. **组合建议**：形成主推产品（高匹配）与交叉组合（组合备选）建议，标注待核实条件。
8. **生成输出**：按 references/output-schema.md 组装候选产品列表。
9. **自检与交付**：对照"交付标准"checklist 自检，通过后交付访前报告组装（SK-FRONT-001）或直接交付客户经理+产品经理。

## 核心分析框架

### 5.1 三源融合匹配（KI-FRONT-006）

| 输入源 | 说明 | 示例 |
| --- | --- | --- |
| KYC 痛点 | 客户经营痛点与财务特征 | 应收账款高企、现金流紧张 |
| 沟通记录需求 | 客户在沟通中表达的需求 | "扩产项目需要资金""想加快回款" |
| 市场信号 | 行业景气与政策信号 | 行业景气上行、设备更新补贴 |

### 5.2 匹配度标签（KE-FRONT-006-02，RUL-FRONT-003）

| 标签 | 含义 | 处理 |
| --- | --- | --- |
| 高匹配 | 三源强指向，硬约束通过 | 主推 |
| 组合备选 | 单一源指向或需组合使用 | 交叉销售候选 |
| 待核实 | 需进一步核实条件 | 标注待核实条件，拜访中确认 |

### 5.3 硬约束规则（KI-RULE-002 / RUL-FRONT-003）

- 产品准入条件（授信政策、客户类型限制）；
- 监管禁止项（如违规用途）；
- 组合互斥规则（如同一授信额度下的互斥产品）。

## 输入要求

输入遵循 ```references/input-schema.md```，最低可用输入为 ```customerId```；```needs```（需求摘要）建议提供。示例见 ```assets/example-input.json```，模拟输入见 ```references/mock-input-data.json```。

## 输出要求

输出遵循 ```references/output-schema.md```：候选产品列表（产品名称、匹配度标签、产品描述、匹配依据、待核实条件）+ 主推/交叉组合建议 + 硬约束未通过清单。

## 风险与边界

- **免责声明**：本技能输出为访前产品建议，不构成授信承诺或产品要约；最终以准入审批与合同为准。
- **禁止行为**：禁止绕过硬约束推荐产品；禁止虚构匹配依据；禁止删除待核实条件。
- **待核验标注**：匹配依据须可追溯（来源类型 + 原始出处）；待核实产品标注"待核实"条件。
- **合规边界**：产品推荐须遵守监管禁止项与行内产品准入制度（KI-RULE-002）。

## 信息不足时的处理

- 无 ```customerId```：请求补充客户编号或客户名称；无法提供则终止。
- 三源输入均缺失：输出"输入不足"说明，不凭空推荐。
- 部分源缺失：仅基于可得源匹配，缺失源在匹配依据中标注"数据不可得"。
- 硬约束无法校验：产品标注"待核实"，不进入主推。

## 交付标准

- [ ] 候选产品含产品名称、匹配度标签、产品描述、匹配依据、待核实条件。
- [ ] 匹配依据可追溯（来源类型 + 原始出处），无虚构依据。
- [ ] 硬约束（准入/互斥/监管禁止项）校验结果显性呈现，未通过产品列入 ```hardConstraintFailures```。
- [ ] 主推/交叉组合建议明确。
- [ ] 待核实产品标注待核实条件。
- [ ] 输出符合 references/output-schema.md 结构。
